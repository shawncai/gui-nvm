# Web 应用开发说明

本目录是本地 Node/nvm 管理应用：界面位于 `src/`，本地服务位于 `server/`。开发、验证和发布时遵守以下约定。

## 开发环境

- 使用 nvm 切换到 Node.js `22.22.3`，包管理器固定为 pnpm `8.15.8`。
- 禁止使用 npm/yarn，禁止未经审查新增依赖或自动升级依赖版本；保留并使用 `pnpm-lock.yaml`。
- 每次任务开始时建立对应 checklist，完成后逐项核对。
- 每次生成文件或目录后，在仓库根目录执行 `dot_clean ./`。

## 界面规范

- 仅使用浅色、中性色界面，保持紧凑三栏布局：窄侧边导航、主要数据区域、右侧检查器。
- 保留顶部面包屑和连接状态、侧栏搜索、标题操作区、搜索/筛选行，以及以表格为主的数据展示。
- 功能性 UI 文字使用 `14px`，次要信息、路径和等宽文字使用 `13px`；保持控件点击区域、键盘可操作性和响应式布局。
- 主操作按钮使用黑色，选中状态使用灰色，文件预览使用白色背景；选中行文字和状态必须保持清晰可读。
- 使用小圆角、克制的边框和阴影。避免大卡片、嵌套装饰边框、重阴影，以及宣传性或冗余解释段落。
- 文案以功能名称、状态和操作为主，版本支持信息保持简洁。

## 本地服务与安全

- 服务仅监听 loopback 地址；不得扩大为局域网或公网可访问服务。
- 保留 Host、Origin、请求来源和会话校验，不得为方便开发而绕过这些检查。
- 保留声明文件的优先级、继承解析、保存前预览与 revision 冲突检测，避免覆盖外部修改。
- 保留文件路径和符号链接安全检查，以及隔离的 Node 安装流程；安装任务不得隐式修改默认版本。
- 禁止硬编码 Secret、API Key 或密码。涉及 SQL 时必须参数化，禁止拼接 SQL。
- 不得把真实本地路径、用户配置或本地管理 API 发布到静态预览或托管站点。

## 构建与验证

从仓库根目录运行以下命令，必须先构建再测试；测试包含对构建产物的校验：

```sh
nvm use 22.22.3
pnpm --dir desktop install --frozen-lockfile --ignore-scripts
pnpm --dir desktop build
pnpm --dir desktop test
```

保留 `.openai/hosting.json`、`worker/index.js`、`scripts/prepare-sites-build.mjs` 和 `tests/sites-worker.test.mjs` 的静态预览构建约定。构建应生成 `dist/client/index.html`、`dist/server/index.js` 和 `dist/.openai/hosting.json`；该预览不得连接或暴露用户的本地管理 API。

需要交互验证时，由执行任务的开发者启动服务并检查界面。验证完成后，关闭本任务启动的服务、独立测试浏览器和沙箱/临时进程，不得遗留后台资源，也不要关闭与本任务无关的进程。
